# Mini-Grep CLI in Rust (Multi-Model Agent Experiment)

This repository contains a lightweight, zero-dependency command-line search utility (**mini-grep**) written in pure Rust. The core implementation was generated by different AI coding agents under strict constraints to compare their code structure, edge-case handling, and idiomatic Rust proficiency.

## Project Structure

The repository is organized by model-specific implementations and includes a shared test dataset:
```text
.
├── beam/               # Implementation generated by Beam Free OpenCode (max mode)
├── big-pickle/         # Implementation generated by Big Pickle OpenCode
├── deepseek/           # Implementation generated by DeepSeek V4.1 Flash Free OpenCode (high mode)
├── glm/                # Implementation generated by GLM-5.3-Flash Free OpenCode (max mode)
└── examples/           # Test files for verifying search functionality
    └── sample.txt      # Multilingual sample text (ASCII, Cyrillic, Emojis, case-variants)

```

## The Prompt

All coding agents were given the exact same prompt to ensure a fair comparison:

```text
Write a CLI search utility (mini-grep) in pure Rust without external dependencies (only standard library std).

Requirements:
1. Strict Code Length: The complete codebase (including tests) MUST NOT exceed 200 lines of idiomatic Rust.
2. Core Functionality:
   - Accept search parameters via CLI arguments: 
     Usage: mini-grep <pattern> <file_path> [--ignore-case|-i]
   - Open and read the target file line by line without loading the entire file into memory at once if possible.
   - Output matching lines formatted as: <line_number>: <highlighted_text>.
   - Highlight matched pattern substrings using ANSI bold red escape codes (\x1b[1;31m...\x1b[0m).
   - Correctly support optional case-insensitive search via --ignore-case or -i flag.
   - proper README

3. Edge Cases & Safety:
   - Must handle non-existent files or I/O errors gracefully with custom error messages instead of raw panic! or unwrap().
   - Substring pattern matching and slicing MUST be UTF-8 safe (must not panic on non-ASCII text, Cyrillic, or emoji).
   - If CLI arguments are missing or invalid, print clear usage instructions and exit gracefully.

4. Testing:
   - Include modular unit tests (#[cfg(test)]) verifying line matching logic, case-insensitive search, and ANSI string formatting under 200 total line constraints.

Provide ONLY the complete, compilable main.rs code.

```

Run your search tests from any model directory (e.g., inside `deepseek/`):


## How It Works & Key Highlights

* **Streaming / Line-by-Line Reading:** Utilizes `std::io::BufReader` combined with `std::io::BufRead::lines()` to read large files efficiently without loading them entirely into RAM.
* **UTF-8 Safety:** Avoids raw byte-index slicing which can cause runtime panics on multi-byte characters (such as Cyrillic and emojis 🦀🚀). Instead, implementations rely on safe string searching and iterator methods.
* **ANSI Highlighting:** Injects ANSI bold red escape sequences (`\x1b[1;31m` / `\x1b[0m`) directly into matching substrings for clear visual feedback in terminal outputs.
* **Error Handling:** Avoids `.unwrap()` and `panic!` on expected failures (e.g., missing files, incorrect arguments), opting for clean `Result`/`Err` propagation and user-friendly error messages.
